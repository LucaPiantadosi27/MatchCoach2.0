Macrostep: 11 - Video analysis pipeline

STATO
COMPLETATO

1. OBIETTIVO

Permettere all'utente di registrare un video tattico (o collegarlo a uno
schema esistente) e ottenere un'analisi asincrona del movimento tramite
worker BullMQ. Il video viene tracciato nello stato PENDING → PROCESSING
→ COMPLETED/FAILED. Se vengono forniti i frame rilevati, il processor li
usa; altrimenti genera un recording di esempio dallo schema collegato.

2. FUNZIONALITÀ IMPLEMENTATE

- Modelli Prisma `Video` e `VideoInsight` con relazione 1:1
- Enum `VideoStatus` (PENDING, PROCESSING, COMPLETED, FAILED)
- `VideoModule` con Service, Controller e Processor
- `POST /api/videos` per creare una risorsa video
- `GET /api/videos` per elencare i video dell'utente
- `GET /api/videos/:id` per dettaglio
- `POST /api/videos/:id/analyze` per accodare l'analisi
- `VideoProcessor` BullMQ su coda `video-analysis`:
  * aggiorna stato PROCESSING
  * costruisce un `MovementRecording` dai frame o dallo schema
  * esegue `MovementAnalysisEngine`
  * chiama `GeminiService` per interpretazione tattica
  * salva `VideoInsight` e aggiorna stato COMPLETED/FAILED
- Collegamento a `MovementAnalysisEngine` e `GeminiService`
- Test unitari per `VideoService`
- Regenerazione Prisma Client

5. FLUSSO DI FUNZIONAMENTO

Creazione:
  Client → POST /api/videos { name, schemeId?, filename? }
  → VideoService crea Video con status PENDING
  → restituisce Video

Analisi:
  Client → POST /api/videos/:id/analyze
  → VideoService accoda job su `video-analysis`
  → Redis/BullMQ
  → VideoProcessor:
    * aggiorna stato PROCESSING
    * recupera Video e Scheme
    * buildRecording: se `frames` presenti usa i frame, altrimenti
      genera recording di esempio dallo schema
    * MovementAnalysisEngine → report
    * GeminiService → interpretation
    * Prisma.videoInsight.upsert
    * aggiorna stato COMPLETED
  → Restituisce { jobId, videoId, status: 'queued' }

10. COME UTILIZZARE

Avviare worker:
  cd apps/api && npm run start:dev

Creare video:
  curl -X POST http://localhost:3000/api/videos \
    -H "Authorization: Bearer <token>" \
    -H "Content-Type: application/json" \
    -d '{ "name": "Partita vs Juve", "schemeId": "..." }'

Avviare analisi:
  curl -X POST http://localhost:3000/api/videos/<id>/analyze \
    -H "Authorization: Bearer <token>"

Requisiti:
  - PostgreSQL con schema Prisma applicato
  - Redis in esecuzione per BullMQ
  - GEMINI_API_KEY opzionale (fallback)

11. DECISIONI TECNICHE

- Pipeline asincrona su BullMQ: coerente con Macrostep 7
- Frame detection non reale: il processor accetta `frames` JSON opzionale;
  in assenza genera un recording di esempio dallo schema
- `VideoInsight` separato da `Video`: mantiene 1:1 e permette aggiornamenti
- Status tracking esplicito: migliore UX per tracciare elaborazione
- Prisma schema esteso con relazioni inverse in `User` e `Scheme`
- Regenerazione Prisma Client per attivare `prisma.video` e `prisma.videoInsight`
- Import relativi usati per compatibilità Jest

12. LIMITAZIONI NOTE

- Nessun upload binario reale (file video non viene salvato su MinIO)
- Nessun estrattore di frame da video (ffmpeg non integrato)
- Recording generato di esempio quando `frames` è assente
- Nessun endpoint per inviare frame rilevati
- Nessuna UI mobile per video
- Non esegue migration su DB; schema Prisma aggiornato ma il database
  deve essere migrato separatamente
